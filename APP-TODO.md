# Twiggli app (FlutterFlow): to-do

- **Update the Firebase SDKs (security patch, within 2–4 weeks).** Firebase warned on 03.11.26 ("[Act Now] Upgrade your Firebase SDKs for Firestore"): the eMudhra CA keys were compromised, and Flutter/iOS Firestore SDKs bake the old certificates into the app, so a forged certificate could let someone on the same network read or change app traffic (logins, profiles, bookings). Project twiggli-production is listed. The app (repo thejijoju/Twiggli, v1.0.33, last commit 19.02.26) still uses cloud_firestore 5.6.9, firebase_core 3.14.0, firebase_auth 5.6.0, firebase_storage 12.4.7, firebase_messaging 15.2.7, cloud_functions 5.5.2, firebase_crashlytics 4.3.7. Steps: raise all FlutterFire packages to the patched versions (several major versions, so some app code may need changes), rebuild and test, publish a new version (e.g. 1.0.34) to the App Store and Google Play, then ask users to update (forced update if possible). Needs Flutter + Xcode and store access, so not doable from a cloud session; Claude can prepare the branch with the package bumps and code fixes plus a build guide. Website and Cloud Functions are not affected (web SDK and server SDK). Guide: https://firebase.google.com/support/guides/compromised-emudhra-intermediate-ca (04.11.26)
- **Roll the Stripe live secret key and the Bunny Stream key.** The app's code holds both in plain text: the full Stripe secret key as the default `apiKey` in `firebase/functions/api_manager.js` (the Stripe API calls), and the Bunny key in `assets/environment_values/environment.json`, which ships inside the app. Roll both in their dashboards, then keep them only in Firebase Secret Manager and have the functions read them there. Rolling the Stripe key breaks the app's Stripe calls until FlutterFlow uses the new one. (30.10.26)
- **Know who signs in with Apple.** Sign in with Apple stays on: switching it off locks out everyone who signed up with it, and the App Store requires it next to Google login. "Hide My Email" users get a relay address (…@privaterelay.appleid.com) that still forwards mail. After any sign-in, ask for name plus phone number or a real email before someone can book. (29.10.26)
- **Tighten the Firestore rules.** Some collections (payments, transactions, Users, stripeaccounts) can be written by any signed-in user. Rules are in `firestore.rules`, published by hand in the Firebase console. (29.10.26)
